They create uniquely marked temporary test records and remove only their own
records/files. Run them before going live, not as uncoordinated checks against
a busy production database. DMS_TEST_BASE_URL selects a different local test URL.

The validated production build was generated in .next-production-check and
tested on loopback port 3001. This was a test, not deployment. The normal website
remains a development server on port 3000. Do not expose next dev to production.
The bridge health check passes, but the scanner was not detected during the final

For a normal release, stop the development website, run npm.cmd run build, then
npm.cmd start. Run the scanner bridge separately on the Windows scanner host.

Required before go-live:
1. Rotate issued passwords/secrets as appropriate. Store credentials securely,
   then remove the plaintext credentials.local.txt file from the deployment.
   .gitignore protects new commits, not copies already shared elsewhere.
2. Configure HTTPS, a trusted reverse proxy/host and restricted network access.
   Verify cookie/origin behavior through that real production HTTPS address.
3. Configure restricted Windows file permissions/service identities and supervised
   startup for the website/bridge. Do not grant broad Windows administrator access
   to the web server. Scanner-service control is separate from DMS roles.
4. Back up SQLite, accounts/session secrets, documents and private scanner captures;
   perform a restore test. Agree a retention policy for captures/diagnostics/trash.
5. Perform browser acceptance checks and one authorized non-sensitive physical
   scan: private/public destination, category, dashboard update, preview, download,
   duplex, cancellation and audit entry. No physical scan was triggered in this
   preparation run. Automated checks are not a penetration test or an uptime SLA.

Not implemented (no fake enabled controls remain): searchable PDF export/text layer,
two-factor authentication, email notifications, automatic archive/backup policies,
cross-device browser preferences, disk quota enforcement or permanent trash purge.
Uploaded PDF page totals are corrected when the local OCR/PDF processor finishes.
The local bridge's in-flight job state is temporary; a bridge/server restart can
interrupt a pending scan. Imported document files and SQLite records persist.
